# Сравнение Junie и OpenCode

## Условия и источники

Сравниваются результаты заданий 1–4 в ветках `junie-fix` (`736b6e4`) и `opencode` (`27a4e9a`), обе созданы от `main`. Для оценки использованы история коммитов, документы и исходный код веток, а также заметки разработчика. В ветке `opencode` первоначальный `ANALYSIS.md` создан Qwen Code (коммит `6db87f1`): поэтому результат этой ветки получен совместной работой Qwen Code и OpenCode. Его анализ нельзя полностью приписать OpenCode.

## Общие ограничения реализации

- В обеих ветках флаг `notified` предотвращает повторное уведомление при последовательных проверках, но чтение записей, установка флага и создание уведомлений не объединены в атомарную операцию с блокировкой. Одновременные запуски задач могут создать дубликаты; сбой между обновлением флага и созданием уведомления может привести к его потере. Это вывод по коду, сценарии конкурентного выполнения отдельно не запускались.
- Обе ветки реализуют персональный мониторинг. Другие предложенные в задании варианты — портфель, история цен в базе и симулятор стратегий — в этом сравнении не заявляются реализованными.
- В текущем окружении для ветки `opencode` выполнен `manage.py check`: ошибок конфигурации Django не обнаружено. Полный запуск приложения, тестов обеих веток и установка зависимостей в чистом окружении при подготовке этого сравнения не проводились. Наличие тестов само по себе не подтверждает их прохождение.
- junie сильно уступает в размере контекстного окна

## Выводы

В этом опыте OpenCode дал более воспроизводимое описание установки зависимостей и более широкое покрытие исправлений тестами. Его версия также сохраняет дробную часть цены, что существенно для мониторинга ценовых уровней. Junie подготовил анализ, требования и работающую по замыслу реализацию мониторинга и  его результат не потребовал отдельного вмешательства для восстановления отображения цены, однако имеет проблему с точностью цены и установкой на чистой машине. Обе реализации уведомлений требуют доработки для надёжной работы при параллельном выполнении задач.

По наблюдениям в процессе работы, Junie оказался удобнее при размещении skills, а OpenCode — при подготовке зависимостей.
